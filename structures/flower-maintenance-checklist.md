# Flower Maintenance Checklist

## ■確認項目

### flower-system-core.md
- 花が「装飾ではない」と明記されているか
- 花が何を可視化するものか書かれているか
- 花の意味が「花言葉固定ではなく、層・条件・挙動で決まる」と書かれているか
- 内面層 / 観測層 / 影層 の3層が定義されているか
- 咲く / 揺れる / 侵食する / 消える / 残る の意味があるか
- 役割一覧が入っているか
- 運用ルールがあるか
- 最後に「この世界で花は何か」の締めがあるか

### flower-role-dictionary.md
- 役割辞典だと最初に分かるか
- 役割を先に決めると書かれているか
- 役割一覧がまとまっているか
- 各役割に定義があるか
- 各役割にキーワードがあるか
- 「揺れ」と「揺らし」の違いが分かるか
- 「感情」と「執着」の違いが分かるか
- 使用手順があるか

### flower-scene-rules.md
- 花を意味なく出さないと書かれているか
- 出現条件が層ごとに分かれているか
- 消失ルールがあるか
- 優先順位があるか
- 主役花のルールがあるか
- 共存可能 / 衝突しやすい組み合わせがあるか
- 光と配置のルールがあるか
- 禁止事項があるか

### flower-layout-guide.md
- 資料化ガイドだと分かるか
- 横3分割レイアウトがあるか
- 1花パネルの構成があるか
- 情報の優先順があるか
- 背景 / フレーム / 色のルールがあるか
- 各層の配置の癖があるか
- 線の使い方があるか
- 資料画像の構成例があるか
- 禁止事項があるか

---

## ■修正が必要なサイン一覧

### 1. 同じ説明が何度も出てくる
- core と scene-rules で同じ内容を繰り返している
- dictionary と core で役割説明が重複している

→ 説明の置き場所が曖昧になっているサイン

---

### 2. 読んでもファイルの役割が分からない
- 冒頭3行で用途が分からない
- タイトルと中身が一致していない

→ そのファイルの目的を書き直す必要がある

---

### 3. 見出しだけ追っても意味が掴めない
- 見出しが抽象的すぎる
- 中に何が書いてあるか予想できない

→ 見出し名の改善が必要

---

### 4. 花の意味が“花言葉説明”に寄りすぎている
- 世界の構造より一般的な花言葉が主役になっている
- この世界独自の役割より、外部知識っぽさが強い

→ 構造資料として弱くなっているサイン

---

### 5. 役割同士の違いが曖昧
- 揺れ / 揺らし の差が見えない
- 感情 / 執着 / 支配 の線引きがぼやける

→ role-dictionary を整理し直す必要がある

---

### 6. 実際のシーンで使うイメージが浮かばない
- scene-rules を読んでも「いつ出すのか」が分からない
- 出現条件や消失条件が抽象的すぎる

→ scene-rules の具体例が足りないサイン

---

### 7. レイアウト資料に落とした時に迷う
- 左右中央の意味が弱い
- 情報の優先順が曖昧
- ビジュアルにした時のルールが決めきれていない

→ layout-guide の補強が必要

---

### 8. スマホで読むとしんどい
- 文章が長すぎる
- 箇条書きが詰まりすぎている
- 空白が足りない

→ 行間整理と圧縮が必要

---

### 9. ファイルを跨いで探しにくい
- 「これどこに書いたっけ？」が頻発する
- どのファイルを見るべきか毎回迷う

→ 4ファイルの役割分担を見直すサイン

---

### 10. 綺麗だけど使えない
- 読むと雰囲気はいい
- でも次の対話や設計で参照しにくい

→ 資料としての実用性が足りないサイン

---

## ■良い状態の目安

- core = 世界の定義として機能している
- dictionary = 用語辞典として引ける
- scene-rules = 演出判断に使える
- layout-guide = 図表化の基準になる

この4つが明確に分かれていれば、花構造の基盤は安定している。
